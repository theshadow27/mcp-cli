## The defect class

Every blocker this sprint was the same shape: **something reports healthy while not being
healthy.** Roughly twenty instances across six PRs.

- `aliases` got the `domain_id` **column** but not the **partition** — and the test asserted
  the column existed. Green while every second domain overwrote the first's phase scripts.
- A `denied` credential mode that did not deny — clearing `GH_TOKEN` *restored* the ambient
  credential via `gh auth git-credential`.
- "bounded at 2s", measured at 15,212ms.
- `-d` filtering **0.4%** of real traffic; the fix reported 99% and actually resolved 19.87%,
  because it measured *reaching a code path* rather than *producing an answer*.
- A `qa:pass` label pointing at a commit nobody verified. I nearly merged the arc's
  foundation on it.
- `mcx claude bye --all` ending every session on the machine, across two projects.

Two sub-patterns worth naming, both found by reviewers:

**Two states collapsed into one value.** `toDomainFilter` answering `undefined` to both
"no scope requested" and "scope requested, unresolved". `classifyAgentTool` answering `null`
to both "not my server" and "my server, unscoped tool" — which silently deleted the `domain`
argument from *every* MCP server call. `getSessionPath` short-circuiting on **presence**
rather than **resolution**.

**A test that supplies what production doesn't.** An injected `DomainSource` that always
returned a root where production returns NULL 99.97% of the time. A fixture whose incidental
hyphen made a guard pass. A test asserting a constant was *passed* rather than a bound
*enforced*. A test that **locked in** a bypass as intended behaviour.

The method that finds the second, stated cleanly enough to mechanize: **delete the guard,
run the concrete-class specs. If nothing goes red the guard is unreachable — either it or
the fake is wrong.** Mutation against a fake-based spec only proves the fake is wired to the
guard. That found a fully deletable guard with all 216 tests still passing.

**And the epic's own answer inherited the disease.** Three `doing-it-wrong` rules were found
passing on the exact input they were written to catch. The thesis is "an invariant a caller
can rationalize past is a function, not prose" — but a rule is code, and code without
adversarial tests reports green. Prose at least never claimed to have checked. **Every rule
needs bypass fixtures asserting `@expect 1` on the inputs it must catch.**

## What the design docs got wrong

The brief asked for this specifically. Four things only visible from inside the build:

1. **The marker location and the recovery story contradict each other.** The design puts the
   import marker in the *legacy* `state.db` so it survives `mcx.db` deletion — and separately
   tells users to recover from a bad import by deleting `mcx.db`. Both are in the docs.
   Reproduced: delete `mcx.db`, restart, daemon comes up on a **completely empty database**,
   silently, at `logger.debug`.

2. **The escape hatch ships after the thing that needs it.** `import-legacy.ts` documents
   `mcx domain import --force` as "the only deliberate re-run" — but the `mcx domain` command
   family is #3035, which was *blocked on* #3034. The recovery path for epic A's root shipped
   in an issue that could not start until the root merged.

3. **"No domain is registered by default" is false.** `importScopesAsDomains` auto-creates a
   domain row per `~/.mcp-cli/scopes/*.json` sidecar on *every daemon start*, with no user
   action, before `mcx domain add` exists. `docs/phases.md` says the opposite.

4. **`docs/domains.md` claimed foreign keys that do not and cannot exist** — no `REFERENCES`
   anywhere, `PRAGMA foreign_keys` never enabled, and `NO_DOMAIN_ID = 0` has no `domains` row,
   so an FK could never be added later without seeding one.

**And the invariant the plan had no vocabulary for:**
> **No PR may close a partition whose recovery command has not landed.**

Three authors tested their own PRs against it and answered **yes, against their own
interest**, with reproductions. None of those was found by review. The mechanical form is
better than the principle: *grep the diff for `listDomains()` / `domains.length` used as a
behavioural switch.* Global (one row anywhere flips behaviour for a caller who did not ask)
needs its recovery command on main first; per-caller is independent. Seconds to run,
and it separated the one broken PR from five sound ones.

## What I did wrong

**I starved the workers.** Three PRs pushed commits that did not touch their open findings —
verified by diff each time. In every case the author was doing work *I* sent: safety
broadcasts, partition audits, a rename decoupling. Each request was correct; collectively
they were a denial-of-service on the workers' actual jobs, and the cost looked like code
failure. Broadcasts and per-PR work need different channels.

**I added scope to a filler and paid for it five times.** #1249 asked for a stderr progress
line. *I* directed the event-bus half; essentially every blocker across rounds 1–4 lived in
the half I added. Then I requested `guardInterrupts` mid-repair and withdrew it two rounds
later. Six rounds on a `low`-scrutiny issue.

**My duplicate-dispatch check was scoped to worktree names, not PRs.** `review-3175-r2` and
`review-3175-r3` are distinct paths and identical roles, so the check passed while producing
two reviewers of record on one SHA reaching opposite verdicts three minutes apart.

**I stopped twice without saying so** — a quota wall at 09:52 (3.5h) and again at 20:48
(67m). A stopped orchestrator and a working one are indistinguishable from outside. The
mitigation that works is one line: mail before the turn ends.

**And I walked past a rule in my own skill.** `run.md:21-32` says that when round 1 finds A
and the fix exposes B and the fix for B exposes C, stop repairing and simplify. #3175 was
three rounds of *the same shape at three different sites* — a reader and a writer disagreeing
about the key, with round 3 reintroducing the silent-empty defect one directory level up.
I dispatched three repairs before the boss quoted my own skill back at me.

## What worked

- **Verdicts written to the PR, naming the head and the round.** The single best process
  change. When an approval turned out to cover an older round's findings, the timeline said so.
- **Verify by driving, not reading.** Every serious defect was found by running something.
  The `denied`-doesn't-deny finding required constructing a real child env and probing real
  `gh` and `git`; reasoning had cleared it twice.
- **Reviewers correcting their own approvals.** One flipped its own `APPROVED` thirty minutes
  later after a second pass found the machine-wide `bye`. A verdict corrected in thirty
  minutes costs a rebase; a wrong approval costs every session on the box.
- **Workers correcting *my* instructions with evidence.** A bad rebase command
  (`git rebase origin/main` across a squash-merge) would have silently reverted the entire
  repaired foundation while looking like a clean rebase. A worker caught it before anyone pushed.
- **The coordinated gate hold.** Load 9.0 → 2.6 in two minutes; a worker that had lost three
  pushes landed immediately. It only works if everyone stops, including `git commit`.

## For sprint 79

1. **Run `mcx phase run` for every transition**, even when overriding the emitted command.
   Guard worth building: *a work item with an open PR that has not left `triage` for >1h.*
   Would have fired on all six by 07:00.
2. **Freeze scope at round 1. Cap fillers at two rounds.** If a filler needs a third, it is
   not a filler.
3. **Put the enumeration instruction in every impl brief**: *name the invariant, then
   enumerate every call site that must uphold it and show the check at each — not the ones
   you added, all of them. A guard at four of five call sites is not a guard.*
4. **Every rule ships with bypass fixtures.**
5. **CI needs a scoped-box matrix entry.** Three defects were invisible here purely because
   mcp-cli itself is not a registered domain. Luck, not design.
6. **The box is the throughput ceiling, not the model.** One gate lease, per-repo, that
   fail-opens after five minutes while reporting healthy (#3138/#2690). Every push runs the
   full 6206-test suite twice via hooks.

## Consolidation addendum (post-halt forensics, closeout session)

Written by the closeout session after the operator halted the run; consolidates the
transcript forensics, the auditor's disposition, and the boss's account above into one
record. Companion documents: `sprint-78-audit.md` (auditor, five-figure ledger),
`sprint-78-disposition.md` (per-finding re-score under the (a)/(b)/(c) bar),
`sprint-78-shutdown-dave.md` (orchestrator shutdown checkpoint), and branch
`meta/boss-state` (the meta-orchestrator's operational state at halt).

**The cost, measured.** ~$1,020 across 17 priced worker/review sessions plus two
orchestrator sessions of comparable size — every one Opus except a single $1.39 Sonnet
QA session. The dominant spend was not generation but **context reprocessing**: workers
produced ~0.5–0.7M output tokens each while re-reading 170–330M cache-read tokens held
idle-hot on standby; the sprint orchestrator re-read 621M over 17h with zero compactions
(75% of its tool calls were status polls); the meta-orchestrator ~499M. Review: ~460M
tokens over ~30 rounds, judged ~40–50% productive — the unproductive half was rounds
spent re-verifying stale verdicts on PRs blocked by an unmerged base or an undecided
design question, plus a mid-sprint severity-bar change that invalidated standing blockers
on three PRs. The timeline agrees: 10 merges by 15:19, then seven hours of review-mill
for exactly one further merge.

**The verdict on the plan.** The issue decomposition was sound — verified edge-by-edge
against the epic afterwards (one correction: C never needed B). The failure was the
sprint *packing*: five partition issues sharing `state.ts`/`ipc.ts`/`docs/domains.md`
run concurrently and stacked on the unmerged foundation; the scrutiny mix inverted
(14/17 medium-high vs the skill's ~15% target); the round caps alive in `review-fn.ts`
but absent from the hand-built loop, exactly as the boss records above.

**What changed because of this sprint** (PR #3219, merged next day): harness-native
subagent lanes replace daemon-hosted worker sessions as the default execution model
(2–3 lanes, fresh context per phase, no idle-hot sessions, ledger-not-context);
review findings must meet a merge-risk bar to block; review caps bind hand-orchestration
explicitly; QA must verify guards by mutation (the "reports healthy about code that
never runs" class drove 14/18 repair rounds); the opinion-agent panel is restricted to
round 1 of gated-class reviews; sticky reviews preserve round history. The boss's six
"for sprint 79" items above remain live; items 1–4 are covered by #3219 and the lane
model, items 5 (scoped-box CI matrix) and 6 (gate-lease fail-open, #3138) are tracked
as issues.
